# 代码问题分析与修复说明

原始代码见 [`原始代码.py`](原始代码.py)（从作业文档中提取，未做任何改动）。

这份文档逐条列出原始代码的问题、成因和修复方式。**所有问题都能让原始代码直接崩掉或
产出错误结果**，不是风格偏好。

---

## 一、致命错误：模块级代码直接执行

### 问题 1｜文件根本无法导入

**原始代码（第 1~3 行）**

```python
# 融合基金持仓和股票的市值，并进行标签化，为下一步的训练提供数据
    merge_position_and_market(position_area, current_quarter, previous_quarter)
# 融合基金持仓和股票的市值，并进行标签化，为下一步的训练提供数据
```

这一段在模块顶层，缩进了 4 个空格，且 `position_area` / `current_quarter` /
`previous_quarter` 三个变量从未定义。

**后果**：`IndentationError: unexpected indent`（或者 `NameError`），
整个文件连 `import` 都做不到，后面所有的 bug 都被这一条挡在门外。

**修复**：删掉模块级的调用，改成 `if __name__ == "__main__":` 下的命令行入口，
参数全部来自 `argparse`（见 `fundlab/cli.py`）。

---

### 问题 2｜`get_stock_label` 用了 5 个未定义的变量

**原始代码**

```python
def get_stock_label():
    ...
    stock_data[current_quarter+'股票流通市值']='0'      # current_quarter 未定义
    stock_data[previous_quarter + '股票流通市值'] = '0'   # previous_quarter 未定义
    ...
    '基金数据分析/数据清洗后/' + previous_year + '年' + fund_type + ...
    '基金数据分析/数据清洗后/' + current_year + '年' + fund_type + ...
```

`current_quarter`、`previous_quarter`、`previous_year`、`current_year`、`fund_type`
在函数签名里没有、作用域里也没有。

**后果**：`NameError: name 'current_quarter' is not defined`。

**修复**：全部收进 `Config` 数据类，由命令行传入（`fundlab/config.py`）。

---

### 问题 3｜`import` 缺失

原始代码里 `pd`（pandas）、`csv` 都没导入，`akshare` 只在 `get_stock_label` 内部导入了
一次，而 `merge_position_and_market` 里用了 `csv.DictWriter`。

**后果**：`NameError: name 'pd' is not defined` / `NameError: name 'csv' is not defined`。

**修复**：在 `fundlab/pipeline.py` 顶部统一 `import csv` / `import pandas as pd`，
`akshare` 的导入放在 `fundlab/market.py` 里并给出友好的缺依赖提示。

## 二、数据正确性错误（能跑，但结果是错的）

### 问题 4｜持仓文件的年份和季度交叉配对

**原始代码**

```python
top_position_current_quarter = pd.read_csv(
    '基金数据分析/数据清洗后/' + previous_year + '年' + fund_type + '型基金...前十大持仓-' + current_quarter + '.csv')
top_position_previous_quarter = pd.read_csv(
    '基金数据分析/数据清洗后/' + current_year + '年' + fund_type + '型基金...前十大持仓-' + previous_quarter + '.csv')
```

当前季度的文件用了 `previous_year`，上一季度的文件用了 `current_year`。

**后果**：文件名和实际季度对不上，读取的是另一个季度的持仓数据，
标签算的是错季度的涨跌幅。这类错误不会报错，只会静默产出错误结果。

**修复**：抽成 `Config.holdings_files()` 统一处理，并提供
`--year-quarter-pairing crossed|straight` 开关。默认保留原始的 `crossed` 行为，
确认你的数据命名规则后可以切到 `straight`。

---

### 问题 5｜`price1` 取的是第一行，不是当前行

**原始代码**

```python
for i in range(len(stock_data)):
    ...
    if len(history_data)>141:
        price1=stock_data.iloc[0,4]        # ← 永远是第 0 行
        outstanding_share1=history_data.iloc[0,6]
        stock_data.loc[i,current_quarter+'股票流通市值']=price1*outstanding_share1
```

循环变量是 `i`，但取价格时写死了 `iloc[0, 4]`。

**后果**：**所有股票的流通市值都等于第一只股票的市值乘以各自的股本**，
除了第 0 行以外每一行全是错的。

**修复**：改为按列名和季度边界取当季真实收盘价（`fundlab/market.py::label_by_return`）。

---

### 问题 6｜`price2` 取的是写死的第 58 行

**原始代码**

```python
price2 = stock_data.iloc[58, 4]
outstanding_share2 = history_data.iloc[0, 6]
```

`58` 是个魔数，且和 `price1` 取的是同一列（第 4 列），但被赋给了不同的季度列。

**后果**：上一季度的市值完全是错的。

**修复**：按季度最后一天定位上一季度的收盘价。

---

### 问题 7｜`begin_price` / `end_price` 与季度无关

**原始代码**

```python
begin_price=history_data.iloc[118,4]   # 任意20交易日的开始价格
end_price=history_data.iloc[141,4]     # 任意20交易日的结束价格
```

`118` 和 `141` 是写死的行号，跟 `current_quarter` 完全无关。行情一旦不足 142 行，
或者抓取区间变化，这两个位置就取到了完全不相干的数据。

**后果**：标签（优/良/中/差）算的是随机某 23 天的涨跌幅，而非当前季度的。

**修复**：以 `current_quarter_end` 为锚点，向前回看 `label_lookback`（默认 20）个交易日。

---

### 问题 8｜用位置下标写标签

**原始代码**

```python
stock_data.iloc[i, 7] = 1  # 优
```

`7` 指的是「标签」这一列在整张表里的位置。这个位置依赖前面追加了
`current_quarter+'股票流通市值'`、`previous_quarter+'股票流通市值'` 两列的顺序，
一旦有人调整列顺序，标签就会被写到别的列上，而且不报错。

**后果**：改列名 / 调列序后标签静默写错列。

**修复**：全部改成 `stock_data.loc[i, "标签"] = ...`，按列名定位。

---

### 问题 9｜`str(bool)` 让条件恒为真

**原始代码**

```python
if (flag==True) and (str(stock_code[2:3]=='6') or str(stock_code[2:4]=='00') or len(stock_code)==8):
```

`str(True)` 是 `'True'`，`str(False)` 是 `'False'` —— 两者都是**非空字符串**，
在 `or` 里永远为真。

**后果**：这一整段校验形同虚设，只要 `flag` 为真就一定通过，
本来想拦掉的非法股票代码全部漏了过去，最终带着错误的 symbol 去请求接口。

**修复**：去掉 `str()` 包装，直接用布尔表达式；并在代码规范化阶段就把
交易所前缀判断做对（`fundlab/market.py::with_exchange`）。

---

### 问题 10｜`except` 之后继续往下走

**原始代码**

```python
try:
    history_data=ak.stock_zh_a_daily(...)
except:
    print('网络原因'+str(stock_code)+'股票的价格数据未爬取！')

#print(history_data)

if len(history_data)>141:      # ← history_data 可能根本没被赋值
```

抓取失败时只打印了一条提示，然后继续执行 `len(history_data)`。

**后果**：`UnboundLocalError: local variable 'history_data' referenced before assignment`，
一只股票抓取失败，整批任务就崩了。

**修复**：失败时 `continue` 跳过该股票并计入失败清单；单只股票出错不影响其他股票。

---

### 问题 11｜股票代码解析方式脆弱

**原始代码**

```python
stock_code=top_position_current_quarter.loc[j,'持仓股票代码'][1:]
if stock_code[0:1]=='6':
    stock_code='sh'+str(stock_code)
if stock_code[0:2]=='00':
    stock_code = 'sz' + str(stock_code)
```

三个问题：

1. `[1:]` 无条件砍掉第一个字符，隐含假设原始值形如 `"1600000"`；
2. 只处理 `6` 开头（沪）和 `00` 开头（深），**创业板 `30`、科创板 `68`、北交所 `8`/`4` 全都没有对应前缀**；
3. 用两个独立的 `if` 而不是 `if/elif`，逻辑上依赖二者互斥。

**后果**：非主板股票拿不到正确的 symbol，抓取失败或抓到错的股票。

**修复**：`fundlab/market.py::normalize_code` 用正则提取 6 位数字（兼容
`600519` / `sh600519` / `600519.SH` / `1600000` 多种写法），
`with_exchange` 按 60/68/00/30/43/83/87/92 规则补全前缀。

---

### 问题 12｜CSV 读取丢前导零

原始代码用 `pd.read_csv(...)` 读持仓明细，pandas 会把 `000001` 解析成整数 `1`。

**后果**：深市股票（`00` 开头）代码失真，前缀判断随之出错。

**修复**：持仓明细用 `dtype=str` 读取（`fundlab/pipeline.py::_read_csv`），
并在 `normalize_code` 里对位数不足的代码左侧补零。

---

### 问题 13｜`iloc[j, 4]` 硬编码股票名称列

**原始代码**

```python
if stock_data.iloc[i,0]==top_position_current_quarter.iloc[j,4]:
```

第 4 列被当成「股票名称」列。持仓明细文件一旦调整列顺序，
匹配就全部失效，且**不会报错**，只是所有股票都匹配不上。

**修复**：优先按列名 `持仓股票名称` / `股票名称` 查找，找不到再退回第 5 列，
并在两种情况都不满足时抛出明确异常。

## 三、流程与健壮性问题

### 问题 14｜`f.close()` 在 `with` 块外

**原始代码**

```python
with open('...csv', 'w', newline='', encoding='utf-8-sig') as f:
    writer = csv.DictWriter(f, fieldnames=header)
    writer.writeheader()
    writer.writerows(merge_position_and_market_value)
f.close()
```

`with` 退出时已经关闭了文件，后面再 `f.close()` 是多余的。

**修复**：去掉多余的 `close()`。

---

### 问题 15｜目录不存在直接崩

原始代码假设 `基金数据分析/处理数据/` 和 `基金数据分析/数据清洗后/` 已经存在。

**后果**：在 GitHub 上 clone 下来第一次跑必然 `FileNotFoundError`。

**修复**：`Config.ensure_dirs()` 自动创建目录；输入文件缺失时抛出带修复建议的
`FileNotFoundError`，而不是一句干巴巴的路径。

---

### 问题 16｜合并逻辑是 O(n²) 双重循环

**原始代码**

```python
for i in range(len(compare_quarterlys_position_number)):
    for j in range(len(compare_quarterlys_market_value_stock_name)):
        if compare_quarterlys_position_number.iloc[i,0]==compare_quarterlys_market_value_stock_name.iloc[j,0]:
```

**后果**：真实数据几千行时，循环要跑几百万次 `iloc` 取值，慢到不可用。

**修复**：改成 `pd.merge(..., how="inner")`，一次搞定。

---

### 问题 17｜没有依赖声明，GitHub 上跑不起来

原始代码是一个孤立脚本，没有 `requirements.txt`、没有入口、没有 CI。

**修复**：补齐 `requirements.txt`（pandas + akshare）、`pyproject` 风格的包结构
（`fundlab/`）、`python -m fundlab` 命令行入口，以及
`.github/workflows/ci.yml`（Python 3.10/3.11/3.12 矩阵测试）。

---

### 问题 18｜抓取没有重试和限速

新浪财经接口「大量抓取容易封 IP」。原始代码一次失败就崩（见问题 10），
也没有任何节流。

**修复**：`fetch_daily` 支持指数退避重试（`--retries` / `--backoff`）、
请求间隔（`--pause`）、本地缓存（`--cache-dir`），以及缺依赖时的友好提示。

---

### 问题 19｜列下标取「流通股本」在 akshare 升级后会静默取错列

原始代码用 `history_data.iloc[0,6]` 取流通股本。akshare 当前版本返回的列是：

```
date, open, high, low, close, volume, amount, outstanding_share, turnover
```

下标 6 是 `amount`（成交额），**不是** `outstanding_share`（下标 7）。

**后果**：算出来的流通市值偏大很多倍，而且不报错。

**修复**：全部改成按列名取（`outstanding_share`），akshare 调整列顺序也不会错。

---

### 问题 20｜`标签` 初始值与列类型

**原始代码**

```python
stock_data[current_quarter+'股票流通市值']='0'   # 字符串
stock_data[previous_quarter + '股票流通市值'] = '0'
stock_data['标签']='3'
```

流通市值列初始化成字符串 `'0'`，后面又要往里写浮点数，列类型会变成 object。

**修复**：统一初始化为 `0.0` / `3`（数值类型），写回 CSV 时类型干净。
