## ⚠️ 先看这里：你的终端是 WSL，不是 Git Bash

你截图里的终端提示符是 `彭忠燕@LAPTOP-S8C6P7C5 UCRT64 ~`，这是 **WSL (Ubuntu)**。
所以：

| 环境 | Windows 盘的路径写法 |
| --- | --- |
| **WSL / Ubuntu**（你的） | `/mnt/d/.workbuddy/statistic/2026-11-13-08-29-26` |
| Git Bash / MSYS2 | `/d/.workbuddy/statistic/2026-11-13-08-29-26` |

之前给的 `/d/...` 在你的 WSL 里不存在，所以报了 `No such file or directory`。
（另外你复制的那行里混进了中文全角引号，所以多了一条 `$'\302\226': command not found`。）

**还有个更大的坑**：你机器上有 4 个 Python，其中 `D:\appTools\python.exe` 是**残缺的**
（有 pandas，但没 akshare、没 pytest）。直接敲 `python -m pytest` 必然失败。

### 👉 推荐方式：双击运行，不用敲命令

```
D:\.workbuddy\statistic\2026-11-13-08-29-26\scripts\作业助手.bat
```

在文件管理器里进到 `scripts` 文件夹，双击 **`作业助手.bat`**：

```
  请选择  [1]=本地验证（可截图）  [2]=推送到 GitHub  [Q]=退出 :
```

- 选 **1** → 自动跑完 CI 全流程，输出直接就是你要的截图
- 选 **2** → 引导你填仓库地址并推送

它会自动挑选装了依赖的那个 Python、缺依赖就自动装、还会校验地址格式。

> 下面阶段二、三、五也给了命令行写法，习惯用终端的话可以看。

## ⚠️ 如果 GitHub Desktop 报 "name already exists on this account"

这说明 `fund-stock-label` 这个仓库**你已经建过了**（网页上先建的那种）。

**没关系 —— 远端是空仓库，直接推上去就行，不用重新建。**

### 解法 A：GitHub Desktop 图形界面（推荐）

1. 关闭当前这个 Publish 弹窗（点 **Cancel**）
2. 顶部菜单 **Repository** → **Repository settings...**
3. 找到 **Remote** 区域（有的版本在 "Primary remote repository"）
4. 填入远程地址：
   ```
   https://github.com/pengzhongyan01/fund-stock-label.git
   ```
5. 保存后，顶部会出现 **Fetch origin** / **Push origin** 按钮
6. 点 **Push origin** → 推完后顶部变成绿色

> **如果第 3 步找不到 Remote 设置**：说明你的 GitHub Desktop 版本比较新/旧，
> 直接用下面的解法 B，或者干脆**删掉远端仓库重建**（Settings → Danger Zone → Delete，
> 因为是空仓库，删了没损失），然后回阶段一重新 Publish。

### 解法 B：命令行（一定能成）

打开 **WSL**（你的环境）：

```bash
cd /mnt/d/.workbuddy/statistic/2026-11-13-08-29-26
git remote add origin https://github.com/pengzhongyan01/fund-stock-label.git
git branch -M main
git push -u origin main
```

推送成功后，**回到 GitHub Desktop 会自动识别**，顶部变成 "Fetch origin"，
不需要再做任何事。

> **如果 git 报 `CONNECT tunnel failed, response 502` 或
> `schannel: server closed abruptly`**：这是代理的问题，不是仓库的问题。
> 检查是不是有代理在拦：
> ```bash
> echo $HTTP_PROXY $HTTPS_PROXY     # WSL 里
> git config --global --get-regexp proxy
> ```
> 如果确认是代理导致的，先临时清掉再推：
> ```bash
> unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy
> git push -u origin main
> ```
> 或者把代理显式配给 git：
> ```bash
> git config --global http.proxy http://127.0.0.1:你的代理端口
> ```

### 解法 C：删掉远端重建（最省心）

远端是**空仓库**，删了没有任何损失：

1. 浏览器打开 <https://github.com/pengzhongyan01/fund-stock-label/settings>
2. 滚到最底下 **Danger Zone** → **Delete this repository**
3. 回到 GitHub Desktop，重新点 **Publish repository**

> 如果你更想保留现有仓库（虽然它是空的），用解法 A 或 B 就行。

> **关于隐私**：远端仓库现在是 **Public（公开）**。
> 作业建议改成私有：GitHub 仓库页 → **Settings** → 拉到最底下
> **Danger Zone** → **Change visibility** → 选 **Private**。
> 老师有你的仓库链接就能看，公开与否不影响交作业。

## 阶段一：在 GitHub 上建仓库（5 分钟）

### 步骤 1. 打开建仓库页面

浏览器打开：<https://github.com/new>

如果没登录，先点右上角 **Sign in** 登录 GitHub 账号。

### 步骤 2. 填表

| 字段              | 填什么                  | 说明                          |
| --------------- | -------------------- | --------------------------- |
| Owner           | 你的账号                 | 保持默认                        |
| Repository name | `fund-stock-label`   | 建议用这个名字，看得懂                 |
| Description     |                      | 可留空                         |
| Visibility      | **Private** 或 Public | 作业选 Private 更保险；选 Public 也行 |

### 步骤 3. ⚠️ 关键选项

页面往下滚，在三个勾选框那里：

- ❌ **不要勾** `Add a README file`
- ❌ **不要勾** `Add .gitignore`
- ❌ **不要勾** `Choose a license`

> **为什么要紧？** 本地仓库已经有 README 和 .gitignore 了。  
> 如果你在网页上勾了，GitHub 会先创建这些文件，推送时会报  
> `error: failed to push some refs` 或 `rejected ... fetch first`，  
> 还得回来解决冲突，白折腾。

### 步骤 4. 点 Create repository

> **成功标志**：跳转到空仓库页面，地址栏是  
> `https://github.com/pengzhongyan01/fund-stock-label`  
> 页面中间有"Quick setup"等字样，说明建好了。

### 步骤 9. 处理登录（关键，容易卡住）

推送时会弹出一个窗口要你登录 —— **这是 Git Credential Manager，正常流程**：

- **方式 A（推荐）**：浏览器自动弹出 → 点 **Authorize git** → 回到终端
- **方式 B**：如果没弹窗，终端会提示
  ```
  Username for 'https://github.com': pengzhongyan01
  Password for 'https://github.com': 
  ```
  这里**粘贴 Personal Access Token**（不是你的 GitHub 密码！）

**没有 Token 怎么办？** 浏览器打开：  
<https://github.com/settings/tokens/new>

- Note 填 `push token`
- Expiration 选个期限
- **勾选 `repo`** 这个 scope（必须勾）
- 底部 Generate token
- 复制那串 `ghp_...`，粘贴到 Password 位置  
  （粘贴时终端不显示字符，是正常的，粘完直接回车）

> **成功标志**：看到
>
> ```
> To https://github.com/pengzhongyan01/fund-stock-label.git
>  * [new branch]      main -> main
> ```
>
> 或者 `branch 'main' set up to track 'origin/main'`。

点进那个 CI 运行记录，看右侧 job 列表：

| job                              | 预期    | 说明          |
| -------------------------------- | ----- | ----------- |
| 单元测试 (Python 3.11 / 3.12 / 3.13) | 每个都 ✅ | 3 个并行，矩阵展开  |
| 代码检查                             | ✅     | 编译检查 + 冒烟测试 |

全部变成**绿色对勾**就是成功。

> **成功标志**：左边的 CI 记录也是绿色对勾，耗时显示 `1m 20s` 之类。

### ❌ 万一是红的怎么办

先看是哪个 job 红了，点进去看失败步骤的最后几行。对照这张表：

| 报错关键词                                | 原因           | 解决                                         |
| ------------------------------------ | ------------ | ------------------------------------------ |
| `requires-python` / `Cannot install` | Python 版本太低  | 本项目已固定 3.11+，若仍报错说明 CI 文件没更新，检查 `git pull` |
| `ModuleNotFoundError: fundlab`       | 目录结构不对       | 确认 `fundlab/` 在仓库根目录（不是多套了一层文件夹）           |
| `FileNotFoundError` 提到 `.csv`        | 跑到了需要真实数据的步骤 | CI 不跑真实数据，出现这个说明 CI 文件被改过                  |
| `Failed to install packages` / 网络超时  | PyPI 偶发网络问题  | 重新运行：Actions 页面点 **Re-run all jobs**       |

> 90% 的情况直接点 **Re-run all jobs** 重跑一次就好了。

## 附：出问题了怎么办

### 推送被拒（rejected）

```bash
# 如果报 rejected，先同步再推
git pull origin main --rebase
git push -u origin main
```

### 忘了改仓库名/用户名

```bash
git remote set-url origin https://github.com/<新用户名>/<新仓库名>.git
git push -u origin main
```

### 提交信息写错了想改

```bash
git commit --amend        # 改最后一次
# 或
git rebase -i HEAD~3     # 改最近 3 次（编辑器里把 pick 改成 reword）
```

### 提交身份不对

```bash
git config user.name "你的名字"
git config user.email "你的邮箱"
git commit --amend --reset-author --no-edit
```

### 想确认 Actions 配置有没有生效

```bash
cat .github/workflows/ci.yml | head -25
```

应该能看到 `python-version: ["3.11", "3.12", "3.13"]`。

### 不想用命令行

GitHub 网页上其实也能传：仓库页面 → **Add file** → **Upload files** →  
把整个文件夹拖进去 → Commit changes。但**会丢掉 .git/ 里的提交历史**，  
而且中文文件名在网页上传时容易出问题，建议还是用命令行。
